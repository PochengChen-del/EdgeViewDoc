## 3. 產品概述與安全定位

EdgeView 為三層式 HMI/SCADA 平台：

- **Client（Designer/Viewer）**：Qt/QML 桌面、瀏覽器（WASM）與 APP。
- **EdgeView Server**：xnginx（地端入口/TLS）、Metadata Service（設定/授權）、Runtime Proxy（Record/告警摘要）、OPC UA Data Agent（Runtime/History）、OPC UA Alarm Agent、OPC UA 設定 UI。
- **資料層**：PostgreSQL（`waxconfig`/`waxalarm`/`waxlog`）、第三方資料庫、InfluxDB、OPC UA Server、Edge365/EdgeHub。

**安全定位**：EdgeView 提供應用層的認證、授權、Session/CSRF、加密設定、稽核與 OPC UA 安全連線；作業系統、硬體、網路分段與實體安全由資產擁有者負責。

## 4. 安全假設與部署前提

1. 後端服務僅綁 loopback，對外僅暴露 xnginx。
2. 正式環境僅使用 HTTPS/WSS；關閉 HTTP `8880` 或將其導向 HTTPS `8881`。
3. PostgreSQL 僅限內網，使用最小權限帳號。
4. 作業系統已加固（更新、最小服務、帳號控管）。
5. OPC UA 連線採 **SignAndEncrypt**，並使用受信任憑證。
6. 已完成 NTP 時間同步（影響 Session、CSRF 時間戳與稽核）。
7. 已依 CRA-01 風險登錄完成組織層級的殘餘風險接受。

## 6. 安裝與初始安全設定

### 6.1 安裝來源驗證

- 安裝包具電子簽章（Advantech + DigiCert、SHA-256、RFC 3161 時間戳）。
- 僅從官方通路取得安裝包；安裝前驗證簽章與雜湊。
- 透過 HTTPS 傳輸安裝包，避免中間人替換。

### 6.2 必做的初始設定

1. **變更預設密碼**：首次登入後立即變更管理者密碼；系統會要求修改後才能後續操作。
2. **建立專用帳號**：避免多人共用管理帳號；依角色建立 Admin/Power/General/Restricted。
3. **設定資料庫帳密**：以環境變數或 Secret 提供，**不得沿用預設帳密**。
4. **設定 Session 金鑰**：`SESSION_SECRET`（≥32 bytes）或由 `aes_secret` 派生；多服務需一致。
5. **設定 TLS**：見 §9；停用 HTTP 或導向 HTTPS。
6. **設定 NTP**：確保時間正確。
7. **設定備份**：見 §15。
8. **設定稽核**：確認登入、設定變更、匯入匯出皆留痕。

> 注意：若未設定 `SESSION_SECRET` 且資料庫無 `aes_secret`，服務會依設計**啟動失敗**（fail-closed），請依部署文件完成金鑰設定。

## 7. 帳號、角色與存取控制

### 7.1 角色

| 角色 | 工程列表 | 繪圖 | 瀏覽 | 配置 | 使用者管理 |
|------|----------|------|------|------|------------|
| Admin | 全部 | 全部 | 全部 | 全部 | P/G/R |
| Power | 限定 | 限定 | 限定 | 限定 | G/R |
| General | 限定 | 不允許 | 限定 | 不允許 | 不允許 |
| Restricted | 限定 | 不允許 | 限定頁面 | 不允許 | 不允許 |

### 7.2 安全區域與級別

- 安全區域：0–63（64 區）。
- 安全級別：0–127。
- 低級別使用者修改高級別資料需切換具權限帳號。

### 7.3 密碼與鎖定

- 預設登入失敗 **3 次鎖定 10 分鐘**。
- 密碼重設由具權限者配發啟動碼，登入後強制設定新密碼；系統無法讀回舊密碼。
- **建議**：使用高強度密碼、定期更換、避免重複使用；管理帳號建議搭配外部 MFA（見 §7.4）。

### 7.4 多因子驗證（MFA）

- 產品**未內建 MFA**。若需符合較高安全等級，請於反向代理或外部 IdP（OAuth2/OIDC/SSO）整合 MFA。
- 未整合 MFA 時，應以網路分段、限制來源 IP、嚴格鎖定與監控補償。

### 7.5 來源差異

| 來源 | 使用者管理 |
|------|------------|
| EdgeHub（BI） | 全部為 Power |
| WebAccess | 可於 WA/EV 管理並同步 |
| OPC UA | 於 EVS 設定頁管理 |

## 8. 網路與連接埠

### 8.1 連接埠

| 服務 | 埠 | 暴露建議 |
|------|----|----------|
| xnginx HTTP | 8880 | 關閉或 301 導向 8881 |
| xnginx HTTPS | 8881 | 對使用者開放（僅必要網段） |
| OPC UA Data Agent（Runtime） | 28886 | 僅經 xnginx `/ua`；勿直接對外 |
| OPC UA Data Agent（History） | 28887 | 僅經 xnginx `/uadb` |
| OPC UA Alarm Agent | 28889 | 僅經 xnginx `/uaam`（注意預設值可能為 8090，部署時統一） |
| PostgreSQL | 5432 | 僅內網 |

### 8.2 網路分段

1. 將 EdgeView Server 置於 OT/控制網段，與 IT 網段以防火牆隔離。
2. 僅開放使用者必要的 `8881`；後端與 DB 不對外。
3. 遠端維護使用 VPN／跳板機，避免直接暴露管理介面。
4. EdgeHub/BI 走 K8s Ingress（HTTPS），地端走 xnginx。
5. 對不支援驗證/加密的 Driver Protocol（如部分 Modbus 部署），必須以 VPN 或專用網路隔離。

### 8.3 不安全的通訊

- Web API/WebSocket 應全程 HTTPS/WSS。
- 明文或無認證的第三方協定**不在產品保護範圍**，請以網路補償控制處理。

## 9. TLS 與憑證管理

### 9.1 伺服器憑證

- 支援三種方式：**Built-in**（內建自簽）、**Create**（建立）、**Upload**（上傳）。
- 內建自簽憑證的 SAN 含主機名與 IP；瀏覽器可能對自簽或名稱不符提出警告。
- 正式環境建議上傳由企業 CA 或公開 CA 簽發的憑證。

### 9.2 用戶端驗證

- 瀏覽器/Client 應驗證伺服器憑證；不要略過憑證警告。
- 若使用自簽憑證，請將根憑證匯入受信任儲存區。

### 9.3 外部連線

- 與第三方資料源、Edge365、OPC UA Server 連線應使用受信任 CA。
- 避免停用 TLS 驗證；若必須使用自簽，請匯入指定 CA。
- 產品已移除全域停用 TLS 驗證；個別 client 若仍停用，請於升級後改為系統 CA／指定 CA。

## 10. OPC UA 子系統安全設定

| 設定 | 建議 |
|------|------|
| Security Mode | SignAndEncrypt |
| Security Policy | Basic256Sha256 或更強 |
| 使用者身分 | 專用帳號 + 強密碼；避免匿名 |
| 應用憑證（PFX） | 由受信任 CA 簽發；妥善保管私鑰 |
| 憑證驗證 | 關閉「自動接受不受信任憑證」；使用信任清單 |
| SHA1 | 拒絕 SHA1 簽章憑證 |
| 連線逾時/重連 | 依現場調整；斷線回 Bad Quality |
| 稽核 | 登入、設定變更、Ack/Process 需留痕 |

設定入口：`https://<host>:8881/sc/opcua`。

> 注意：Data Agent 的 CORS、時間戳中介層與憑證自動接受屬已知待強化項目（RID-EV-025/028/035，見 §19），部署時請以反向代理與網路控制補償。

## 11. Session、CSRF 與時間

| 項目 | 說明 |
|------|------|
| Session | 儲存於 PostgreSQL `http_sessions`；預設有效期 7 天 |
| Cookie | `Secure`/`HttpOnly`/`SameSite`（依部署與版本） |
| CSRF | 狀態變更請求需帶 `csrfToken` |
| WebSocket 登入 | 以 handshake 的 `graphicSession` 綁定；只比對該 Session 的 `csrfToken`，不掃描全部 Session（R-007） |
| 時間戳 | 寫入操作需 `packetTimestamp`，預設容許 300 秒 |
| 逾時 | WebSocket 連線需於 10 秒內完成登入 |
| 金鑰輪替 | 以 `SESSION_SECRET_PREVIOUS` 保留至少一個 session timeout |

**建議**：縮短 Session 有效期、啟用 HTTPS、確保 NTP 同步、登出後確認 Session 失效。

## 12. 資料保護

| 資料 | 保護方式 | 使用者注意 |
|------|----------|------------|
| 資料源密碼/敏感設定 | AES-256 加密 | 金鑰不得外洩；備份需保護 |
| 使用者密碼 | 雜湊儲存 | 目前為 SHA-256（未加鹽），列為待強化（§19） |
| 傳輸 | HTTPS/TLS | 禁止明文 |
| 匯出檔 | 依權限匯出 | 匯出檔含設定，需加密保存 |
| 日誌 | 稽核 checksum | 避免記錄密碼/Token |

**建議**：資料庫與備份採加密儲存（TDE／磁碟加密）；匯出檔存放於受限目錄；定期檢視存取權限。

## 13. 日誌與稽核

- 稽核事件：登入成功/失敗、登出/逾時、設定變更、使用者/權限變更、匯入/匯出、DB 操作、API 拒絕、稽核查詢。
- 稽核記錄含 SHA3-256 checksum，可驗證未被竄改。
- 可於 UI 查詢與匯出稽核日誌。

**建議**：

1. 將日誌集中至 SIEM 或外部儲存。
2. 限制可刪除日誌的角色。
3. 設定容量與保留期限告警。
4. 定期抽查 checksum 與異常登入。

## 14. 更新與修補

### 14.1 更新原則

- 僅使用官方簽章安裝包（Advantech + DigiCert、SHA-256、RFC 3161）。
- 更新前備份資料庫與設定。
- 於測試環境驗證後再套用至正式環境。
- 產品**不阻擋降版**；請依 Release Note 確認漏洞修正版本，避免降回含漏洞版本。

### 14.2 更新步驟（建議）

1. 閱讀 Release Note 與安全公告。
2. 備份 `waxconfig`/`waxalarm`/`waxlog` 與憑證。
3. 驗證安裝包簽章與雜湊。
4. 停止服務（依服務管理順序）。
5. 安裝更新並確認版本。
6. 啟動服務並執行煙霧測試（登入、畫面、Record、OPC UA、告警）。
7. 檢查日誌與服務狀態。

## 16. 服務管理與可用性

- 可於 `/system` 檢視/開關服務：EdgeView、Action log maintain agent、Record proxy service、OPC UA client agent、OPC UA client agent (history)。
- 服務支援自動啟動；異常崩潰由 watchdog 重啟。
- xnginx 提供限流；高負載時請調整門檻並監控。

**建議**：設定健康檢查、告警與容量監控；避免單一帳號同時大量連線；定期檢視 `[recorddata] stats`。

## 17. 安全操作建議（給操作員）

1. 不使用共用帳號；離開座位請登出或鎖定。
2. 不開啟來源不明的專案、腳本、插件或模型。
3. 不下載/執行未經授權的程式或檔案。
4. 不將密碼寫在便條或共用文件。
5. 發現異常（不明登入、畫面異常、告警異常）立即通報管理者。
6. 不擅自變更網路、憑證或安全設定。

## 19. 已知限制與殘餘風險

以下為已知限制，請以部署與流程補償（詳 CRA-01 §9、CRA-02 §9）：

| 項目 | RID-EV | 影響 | 補償建議 |
|------|--------|------|----------|
| 未內建 MFA | RID-EV-008 | 帳號遭竊風險 | 外部 IdP/反向代理 MFA |
| 密碼雜湊為 SHA-256（未加鹽） | RID-EV-009 | 離線破解風險 | 限制 DB 存取、強密碼、待升級 Argon2id/bcrypt |
| 無同時 Session 上限 | RID-EV-010 | Session 濫用 | 監控、縮短有效期 |
| 稽核日誌可被管理者刪除 | RID-EV-053 | 滅證風險 | 外部 SIEM/WORM、分權 |
| 部分服務仍可用 HTTP `8880` | RID-EV-039 | 明文傳輸 | 關閉或導向 HTTPS |
| 個別外部 client 停用 TLS 驗證 | RID-EV-040 | 中間人風險 | 改指定 CA；網路隔離 |
| Data Agent CORS/時間戳/憑證自動接受待強化 | RID-EV-025、028、035、036 | 越權/重放/偽造 | 反向代理白名單、信任清單、網路控制 |
| 預設 DB 帳密 | RID-EV-002、065 | 未改設定即暴露 | 以 Secret/環境變數覆寫並檢查 |
| 明文第三方 Driver Protocol | RID-EV-027、039 | 竊聽/重放 | VPN／專用網路 |
| 無容器化/硬體加密模組 | RID-EV-029、046 | 隔離/金鑰保護有限 | OS 硬化、憑證存放區、CSPRNG |

## 20. 停用與資料處置

1. 匯出並備份必要專案與稽核資料。
2. 撤銷使用者帳號、Session、API Token 與裝置推播 Token。
3. 移除憑證與私鑰（含 PFX）。
4. 依組織政策刪除資料庫與備份（含 `waxconfig`/`waxalarm`/`waxlog`）。
